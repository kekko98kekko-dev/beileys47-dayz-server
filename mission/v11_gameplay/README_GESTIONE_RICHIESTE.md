# BEILEYS47 Gameplay V11 — implementation ledger

**Scope:** Livonia PS4/PS5, DayZ 1.30. **ALL files in this directory are STAGED in GitHub, NOT LIVE on Nitrado, NOT tested in game.** Live server has players during this work: no restarts, no wipe, no write changes. 

## Prepared as supported configurations

1. **Categorized trial inventory** — `beileys47_test_items_v11.json`: 57 **unique, valid Livonia item classnames** organized in six tents from the existing Scalespeeder Dolnik military base. No extra tents. Medical A: 9, Medical B: 8, Food/water: 8, Firearms: 10, Ammo: 10, Vehicle/building tools: 12. Existing tents are located in `TEST_ITEMS_POSITIONS_AND_LIMITATIONS.md`. The Y coordinates come from original source tent anchors +0.35 m and **ARE NOT ground/physical proofs**. This test file is OPTIONAL, temporary and must not be loaded on a public server before PS5 floor/ceiling verification. No guarantee of all thousands of DayZ usable items; it's a practical sample.
2. **Every newly spawned supported vehicle** — `beileys47_vehicle_loadouts_v11.xml` for 17 vanilla vehicle classnames. Includes each original Bohemia 1.30 attachment definition **plus** a 100%-configured Canteen, full CanisterGasoline and TireRepairKit in vehicle cargo. 100% chance is configuration intent; game cargo space and existing persisted vehicles still control results. Canteen quantity is full, but sterile/clean drinking-water contents cannot be inferred from numeric quantity alone. For covered M3S vehicles also three attachment cargo stacks at 50% max: `WoodenLog`, `WoodenPlank`, `MetalPlate`; game typically supports 50 logs max on M3S, hence 25 logs desired. These slot placements are based on community-tested templates but require direct PS5 validation. 
   - **Installation:** do NOT overwrite `cfgeconomycore.xml` blindly; conservatively add the `<file name=... type="spawnabletypes" />` line in the existing `<ce folder="custom">` section, or merge these types into the live `cfgspawnabletypes.xml` while retaining all actual prior modifications. **DO NOT configure both**. See complete original-file registration reference `cfgeconomycore_V11_REFERENCE_DO_NOT_OVERWRITE.xml`. Custom definitions may override wheel probabilities; need a diff against ACTUAL live file before activating. Changes affect **newly spawned vehicles**, not already-existing persistent vehicles.
3. **Sunny and no precipitation** — `cfgweather_SUNNY_V11.xml`, based on official Livonia 1.30 schema: `reset=1 enable=1`, fog/rain/snowfall current and limits zero, overcast 0..0.12, no lightning. Wind left as vanilla. This can remove DayZ dynamic fog and rain, but cannot disable all scene effects like nighttime visibility, draw distance, or other rendering phenomena.
4. **Truck event targets** — `db_event_VehicleTruck01_FRAGMENT.xml` has active fixed event nominal10/min10/max12 and restock0, 12 existing Bohemia official truck positions selected geographically spread out via `cfgeventspawns_truck12_FRAGMENT.xml`. Position separation >=2904 m, none close to Dolnik base. **WARNING:** a truck that a player drives away is still an active vehicle in the CE count. These files **do not** spawn a free replacement every time someone drives a truck away. A new spawn normally occurs only when the economy frees/loses that vehicle count, e.g. cleanup of a ruined vehicle, with safe-radius requirements. Existing vehicle persistence unaffected.
5. **New lumber piles start full** — `db_types_PileOfWoodenPlanks_FRAGMENT.xml` sets `quantmin=100 quantmax=100`, which requests full quantities for future piles; the pile's game maximum is 252. **WARNING:** existing depleted piles are NOT automatically topped up at a fixed date. The source's untouched lifetime is 28800 seconds. Do not misrepresent it as a 15-day reset.

## NOT feasible as unconditional stock PS5 XML guarantees

- **Each stolen/moved truck instantly replaced at its spot:** Central Economy counts active persistent vehicles even when moved. To duplicate a truck after moving it would require external state/commands, with duplication and abuse risks. Not implemented; event target is the supported approximation.
- **All wood piles magically return to 252/252 exactly every 15th calendar day:** DayZ CE has restock and lifetime for *new instances*, no guaranteed per-entity calendar refresh. Requires a tested external scheduled operator capable of manipulating correct persistent objects or a supported in-game API; not implemented. The safe supported approximation is full quantity on newly generated piles.
- **Every one of thousands of usable classes as free physical loot in six tents** on a 10-player server is not a sensible release default, may cause performance problems, and cannot be guaranteed by a simple loot economy without validation. This V11 contains 57 important functional objects, with a later opt-in catalog if a PS5 test verifies safe geometry.
