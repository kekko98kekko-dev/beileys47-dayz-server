# ZONA 47 — Stage 4.1: Automated Livonia site screening

**This is a survey shortlist, NOT a selected or playable ZONA 47 location.** Nothing changes on DayZ, PS4, PS5 or Nitrado.

## Why this stage exists

ZONA 47 requires a ~240 × 220 m tactical layout with three independent entry concepts. Putting it on randomly chosen world coordinates would risk existing terrain geometry, unseen trees, roads, dynamic events and poor combat design. An automatic spatial pre-screen can discard some obvious conflicts **before** the costly in-game survey.

## Reproducible data

From the pinned Bohemia Interactive DayZ-Central-Economy Livonia mission commit `f220b2918b1d79a5055b1ee9be70c0ec1516e876`:

- `mapgrouppos.xml` supplies *terrain group anchors*, not full dimensions of buildings or vegetation.
- `cfgplayerspawnpoints.xml`, combined with the current Stage 1 rule names (Brena, Sobotka, Kolembrody), supplies the actual fresh-spawn position samples.
- `cfgeventspawns.xml` supplies dynamic event position anchors, including vehicles, helicopters, military convoys, police scenes, contaminated areas and trains. A fourth source, `db/events.xml`, is cross-checked so only **active** named events are considered.

The screening never alters these upstream files. All input content hashes are recorded in the report.

## Three region hypotheses

- **Central military approaches** — first to physically survey, because with 10 slots a site not excessively far from the northern fresh-start area may be easier to encounter; this is a **design hypothesis**, not validated traffic.
- **South-west wilderness corridor** — possible strong survival progression; concern: low natural player traffic for 10 slots.
- **South-east approaches** — alternative regional identity; concern: travel and access.

These regions are **coordinate bounding boxes**, not claims about a specific named settlement or road. In particular, this report does not verify the earlier verbal description “Nadbór to Swarog”.

## Automated filtering (internal heuristics, not DayZ engine rules)

- Sample one center every 200 m in each region.
- Exclude centers under 1.8 km from any of the 15 currently targeted fresh-spawn samples.
- Exclude centers closer than 350 m to included event spawn anchors.
- Exclude centers closer than 240 m to any terrain group anchor; still not proof of an empty footprint.
- Require at least two military terrain anchors within 1.8 km and the nearest 350–1700 m away, providing nearby progression without building directly on an existing military cluster.
- Check for no terrain group anchors within 230 m and score lower for clutter within 500 m.
- Select up to three separated centers per region (at least 400 m apart), with a preference for moderate travel from the active spawns.

All limits are **our initial design filters** and may be refined with actual game evidence. A terrain group is only an anchor: an unseen wall, woodland, stream, slope, static building, trigger or road can still invalidate a point.

## Deliverables

GitHub Actions generates these non-installable outputs:
- `dist/stage4_site_screening/site_screen_report.json` — nine provisional X/Z candidates at most, score and nearest-anchor metrics, sources and limitations.
- `dist/stage4_site_screening/site_screen_scatter.svg` — coordinate scatter view. It is **NOT** a road, height, vegetation, satellite or playable map.
- `dist/stage4_site_screening/beileys47-zone47-site-screen-only.zip` — verified ZIP with reports and prominent *do not deploy* warning.

The screening is tested with independent distance and exclusion checks against the official pinned inputs. It cannot certify a complete object footprint or map performance.

## To move from shortlist to physical approval

1. On a real Livonia map / game session, inspect the highest-scoring central-region coordinates and the two alternatives.
2. Confirm the correct game coordinate system, ground heights, slope, roads, vegetation and absence of interfering static structures. Existing official XML does not provide these details.
3. Walk the site and test three approaches, cover rotation and the Overwatch Ridge idea; reject a location where only one tactical route is feasible.
4. Measure 26 actual Y heights and rotations only **after** the site is accepted.
5. Verify Object Spawner support and selected model classes on the target PS4/PS5 version, then generate an **offline preview only** using the already guarded exporter.
6. Only after separate authorization, backup and real console test may any Stage 4 configuration be installed on Nitrado.

**No terrain verified = no export, no live deployment, no performance claim.**
